# quire: what the app claims about itself

The store listing, the data safety form and the README are filled in from this
page. Anything that adds a permission, a dependency or a claim is written here
in the same change, with the reason.

## Network

- No `INTERNET` permission. Android refuses socket creation for the app's UID,
  so no dependency can reach the network even by accident.
- Data collected: none. Data shared: none.

## Dependencies that bring native code

- `flutter_quill` (MIT) sets a Word document, and the words typed on a
  slide, in the editor. It brings
  `url_launcher`, which adds a WebView activity to the manifest, not
  exported, so no other app can start it. quire never opens a link in a
  document: the editor's link handler does nothing, and with no `INTERNET`
  permission nothing could load in it anyway. No permission is added.

## Permissions (release APK)

| Permission | Visible to users | Why |
|---|---|---|
| `POST_NOTIFICATIONS` | Yes, asked on Android 13+ when the first folder is handed over | The notice that a document arrived in a folder quire reads |
| `RECEIVE_BOOT_COMPLETED` | Listed, never asked | Keeps the look for new documents scheduled after a restart. WorkManager would add the same permission |
| `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` (signature level, generated by androidx) | No | `registerReceiver` on Android 13 and above |

The store listing can no longer say "no permissions". It can still say "no
network and no data collected": neither of these reaches the network.

## Folders on the phone

- Read through the Storage Access Framework: the reader picks a folder once
  and the grant is persisted. No storage permission, no
  `MANAGE_EXTERNAL_STORAGE`, and no Play Console declaration. quire reaches
  only the folders it was handed.
- Documents in them are read in place, never copied, and parsed only when
  opened. Making a folder inside one makes it on the phone.
- Android only for now. On iOS the row is not offered: the Swift side has not
  been written, because iOS has never been compiled here.

## Edits

- An edit never writes to the document it came from. Each save is a revision
  in the app's own storage (`revisions/`, beside the imported library),
  numbered and never renumbered, with the original always kept. A document in
  a folder on the phone is never written to.
- At most 20 revisions or 100 MB a document, oldest dropped first, never the
  one being read. Deleting a revision, or forgetting the others, asks once and
  says it cannot be undone. Deleting a document for good deletes its
  revisions.
- A spreadsheet formula quire writes carries no value: quire does not work
  formulas out. The workbook is marked to be calculated when next opened
  elsewhere, and quire shows the formula as written until then.
- PDF edits are annotations with their own appearance, added in an
  incremental update. The page's content stream is not rewritten, and a
  sealed file stays sealed under its own key. Words a standard PDF font
  cannot set are written in Inter, cut down to the letters used, and words
  in scripts Inter lacks are written as a picture of what the editor drew.
  Taking a comment off takes its replies with it, as Acrobat does.
- A Word document is edited in place. Paragraphs nobody touched, tables,
  pictures, fields and section breaks are written back as they were; a
  changed paragraph keeps its own properties and each character's run
  properties.
- A deck is edited in place. Only the slides, layouts, masters and themes an
  edit changed are written again, and every other part is copied across as it
  was; a save leaves out the parts nothing points at any more, such as a
  deleted slide's pictures and charts.
- A CSV file is written back row by row: rows nobody touched keep their own
  text, quoting and line endings, and each save is read back before it is
  kept.
- Revisions sit in the same storage as the library, so the backup rules
  below cover them.

## Backup

- `android:allowBackup="false"`, `android:fullBackupContent="false"`, and
  `dataExtractionRules` excluding every domain from both cloud backup and
  device transfer, which Android 12 and later need on top. The imported
  library is not copied to the owner's cloud account or to a new phone.
  Uninstalling the app deletes it.

## Notices

- A job on the phone's own scheduler looks in the adopted folders about every
  15 minutes, whether or not quire is running. A notice comes a while after a
  download lands, never the moment it does. The first look at a folder only
  learns what is already there.
- Channel `new_documents_v1`, high importance, with the generated knock
  (`tool/build_knock_sound.dart`). A released channel's sound and importance
  cannot change: a new sound needs `new_documents_v2`.

## Formats offered to other apps

PDF, DOCX, XLSX, PPTX, CSV and TSV, Markdown and plain text. The old `.doc`,
`.xls` and `.ppt` binaries are not claimed, because quire cannot read them yet.

## Encryption

`lib/pdf/crypt.dart` implements RC4 and MD5 to open and seal password
protected PDFs. This matters for the iOS export compliance answer and has not
been researched yet.
